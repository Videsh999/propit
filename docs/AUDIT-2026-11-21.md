# Production readiness audit — 21 November 2026

## Decision

Local application checks pass. **Public launch remains blocked** until the actual PropIT Supabase
project is accessible, configured and tested with real providers and approved inventory.
This is not a claim that every possible device, outage or traffic level is error-free.

The connected Vercel team exposes the `propit` project linked to `Videsh999/propit` on `main`.
The connected Supabase account currently returns only `review orm` and `ReviewAi`, both inactive.
No unrelated database was modified and no new project was created. Vercel currently has no Supabase
environment variables. Actual email delivery, Google OAuth, hosted RLS and live customer submissions
could not be verified against PropIT's cloud configuration.

The first pushed production deployment reached the new readiness gate on Vercel and was blocked
for missing Supabase keys, request protection secret and a valid canonical HTTPS origin. The prior
deployment was retained. This confirms the gate runs on the hosting platform too.

## Defects addressed

| Finding | Change and verification |
| --- | --- |
| No customer authentication | Added Supabase SSR sessions, email links, Google flow, safe callback destinations and sign-out |
| Customer state existed only in local browser storage | Added private Supabase state, optimistic versions, conflict merge, offline retry and separate per-account storage |
| Viewing enquiries disappeared on restart | Replaced process memory with authenticated, RLS-protected records and idempotent retries |
| Seller wizard claimed success without saving | Added validated pending submissions; success appears only after durable acknowledgement |
| Demo inventory could be deployed as real listings | Production serves only validated published snapshots; missing services/data block the Vercel build |
| Rental sorting used purchase prices | Monthly-rent sorting now covered by a regression test |
| Viewing date followed UTC | India calendar dates and impossible-date validation are covered by tests |
| Internal localhost normalization broke local origins | Redirect and CSRF handling now preserve the actual loopback host; HTTP regression covers it |
| Unbounded request bodies and paid AI abuse | Stream size limits, validation, origin checks, shared database budgets and authenticated paid AI |
| Missing browser defenses/error recovery | Nonce CSP, security headers, private cache rules and retryable error boundaries |
| Vulnerable framework/dependencies | Updated Next.js to 16.4.6 and patched audited dependencies; production audit reports zero vulnerabilities |
| Truncated map matches | All filtered matches reach map points; visible cards remain paginated |
| No repeatable release checks | Added GitHub Actions, real Postgres migration tests, HTTP acceptance and a production dependency gate |

## Results

- ESLint with zero warnings: passed.
- Optimized Next.js build and TypeScript: passed.
- 14 automated test groups: passed. Coverage includes redirect attacks, numeric/range bounds,
  dates, request bodies, bursts, tenant switching/restoration, corrupted storage, conflict merging,
  catalog references and production mode enforcement.
- Migration executed successfully in local PostgreSQL through PGlite. Anonymous/private access,
  owner isolation, rejection of direct customer submission writes, duplicate references, optimistic update conflicts,
  public catalog switching and service-only budget permissions: passed.
- Full API/page regression script: passed, including map zoom levels, markers, anchors, radius,
  polygons, filters, natural search, localities, comparison, assistant sources, project/property
  routes, assets and unknown-resource 404s.
- HTTP security tests: passed. Confirmed per-response CSP nonces on scripts, no-store responses,
  cross-site rejection, body caps, protected account access, safe callbacks and burst 429 recovery.
- Local search load: 100 requests, 10 concurrent clients, zero errors; p50 **12 ms**, p95 **14 ms**,
  maximum **22 ms**. These measure a local generated catalog without production Supabase network
  latency; they do not establish public internet performance or production capacity.
- Browser checks: map rendering, Gachibowli scoping, selection to full property details, enquiry
  unconfigured state, comparison addition/removal, grounded comparison answers and source links.
  Desktop, 390px mobile and 768px tablet layouts were exercised; mobile home/comparison had no
  document-width overflow. No browser console errors were observed during these exercised flows.
- Production readiness command: correctly fails with missing required configuration. This is an
  expected launch safeguard, not a passing hosted acceptance test.

## Remaining release dependencies

1. Access to the real PropIT Supabase project, schema inspection, migration and hosted security checks.
2. Canonical domain and secure Vercel environment configuration; real email SMTP and Google OAuth setup.
3. Approved real inventory and licensed property media/documents, reviewed before catalog publication.
4. Two-account provider, session-expiry, cross-device, submission/retry and outage acceptance checks.
5. Enquiry handling owner, real customer policies/support, backup/restore verification and monitoring.

The migration and release instructions are in [PRODUCTION.md](PRODUCTION.md). Pending requests do
not automatically notify a builder or confirm an appointment. The admin portal, payments and live
transaction feed remain outside the implemented feature set.
